# Архитектурный атлас Тбилиси

Клиентское статическое приложение на React, TypeScript, Vite и Leaflet. 100 зданий на карте исторического центра Тбилиси, фотографии, каталог, поиск, фильтры, локальная подложка и определение местоположения по запросу пользователя.

Каталог расширен автоматизированным отбором объектов, отмеченных как исторические или охраняемые в OpenStreetMap, с дополнением данных Wikidata. Новые карточки, архитектурные атрибуции, фотографии и права требуют редакционной проверки. Неизвестные данные не заполняются предположениями. В текущем наборе фотографии есть у 73 объектов, из них у 45 — несколько; ещё 27 пока без фотографий. Дата представлена у 34 объектов.

## Готовый сайт

Каталог `dist` можно положить на любой статический HTTPS-хостинг. Для локальной проверки:

```sh
python3 -m http.server 8000 --directory dist
```

Откройте `http://localhost:8000/`. Для GitHub Pages копируйте содержимое `dist` в корень выбранной публикационной ветки. Атлас также работает в подкаталоге, например `https://username.github.io/repository/`.

`file://` не поддерживается. Для геопозиции и проверки SHA-256 нужен HTTPS или `localhost`. Данные атласа и фотографии загружаются из локального пакета. Фоновая карта всего Тбилиси загружается тайлами с OpenStreetMap при перемещении и изменении масштаба, поэтому для полной подложки нужен интернет; в центре остаётся упрощённая локальная карта. Тайлы не скачиваются заранее. Запуск закрытой страницы без сети (PWA) не реализован.

## Исходники

Нужны Node.js и npm:

```sh
npm ci
npm run check
npm test
npm run build
npm run verify
npm run dev
```

Для live-разработки в Docker выполни `make dev` и открой `http://localhost:5173/`. Сервер пересобирает изменённые модули и обновляет страницу без перезапуска; проверка изменений работает через опрос файловой системы, в том числе при Docker bind-mount. Чтобы выбрать другой локальный порт, укажи, например, `make dev DEV_PORT=4173`.

- `src/` — интерфейс, Leaflet-карта и геопозиция, галерея, локальные поиск и фильтры.
- `public/atlas/buildings.json`, `basemap.geojson`, `photos/` — данные и медиа текущего атласа.
- `raw/osm-tbilisi-selected.json` — выборка из административной границы Тбилиси: улицы, парки и музеи без общей карты зданий.
- `data/heritage-extra.json` — 90 дополнительно отобранных объектов; `data/geometry-overrides.json` — геометрия отношений OSM для первоначальных объектов.
- `data/editorial_sources.json`, `data/gallery-sources.json` и `data/curated-extra-photos.json` — атрибуции и пути медиа.
- `scripts/build-data.py` — сборка объектов и подложки из данных, `raw/osm-grid-*.xml` и выборки городских слоёв; `scripts/create-manifest.mjs` — размеры и SHA-256.
- `scripts/build-heritage-extra.py` и `resolve-geometries.py` используются только при повторной подготовке исходных геоданных и дополнительно требуют Python-пакет Shapely.

Чтобы пересоздать данные из приложенных OSM-выгрузок и локальных редакционных файлов, выполните `python3 scripts/build-data.py`, затем `npm run build`. Скрипты загрузки предоставлены для исследования и требуют сети; повторная выгрузка внешних источников может изменить исходные данные.

## Публикация в GitHub Pages

Из корня репозитория с исходниками:

```sh
bash deploy-pages.sh
```

По умолчанию скрипт собирает текущую рабочую версию и отправляет только содержимое `dist` в ветку `origin/gh-pages`. Историю ветки сохраняет; существующие файлы не удаляет, но файлы с совпадающими именами обновляет. Исходную ветку и индекс не переключает. Временную папку не удаляет и показывает её путь. Для другого remote или ветки:

```sh
PAGES_REMOTE=origin PAGES_BRANCH=gh-pages bash deploy-pages.sh
```

В GitHub необходимо один раз открыть Settings → Pages и выбрать Deploy from a branch → `gh-pages` / `(root)`. Скрипт использует текущие файлы, даже если они ещё не закоммичены.

## Публикация через Docker

Из корня полного Git-репозитория с исходниками (включая `index.html`, `src/`, `package.json` и `package-lock.json`, а также Docker-файлы):

```sh
make image
make build
```

`make build` соберёт сайт и запишет результат локальным коммитом в `gh-pages` внутри подключённого репозитория. Контейнер не делает push и не требует SSH-ключей или сетевого доступа к Git remote. Подключённая папка доступна на запись, поскольку контейнер обновляет Git-ветку. Имя и email автора коммита берутся из Git-конфигурации на хосте. Чтобы отправить ветку:

```sh
make push
```

Remote и ветку можно переопределить: `make build REMOTE=upstream BRANCH=site-pages`, затем `make push REMOTE=upstream BRANCH=site-pages`.

### Codex CLI в Docker

Образ также содержит Codex CLI и `bubblewrap` для Linux-песочницы. Запусти CLI из корня проекта:

```sh
make image
make codex
```

Команда запускает интерактивный `codex --no-daemon --dangerously-bypass-approvals-and-sandbox` в `/workspace`: Codex не запрашивает подтверждения и не применяет свою внутреннюю песочницу. Изоляцию обеспечивает Docker: процесс работает с UID/GID пользователя, без Linux capabilities и повышения привилегий; корневая файловая система контейнера доступна только для чтения, `/tmp` — временный `tmpfs`. Запись разрешена в смонтированный `/workspace` и отдельный том `/codex`. Настройки и вход хранятся в томе `atlas-codex-home`, а не на хосте и не в образе. Первый вход выполни так:

```sh
make codex ARGS="login --device-auth"
```

После авторизации запускай `make codex`; данные останутся в томе между контейнерными сессиями. Чтобы выбрать другое имя тома: `make codex CODEX_VOLUME=my-codex-home`. Для других аргументов, например версии CLI: `make codex ARGS="--version"`. Режим Codex с максимальными правами действует внутри доступов контейнера: он может свободно менять файлы в `/workspace` и `/codex`, а также обращаться к сети. Docker при этом не запускается в `--privileged` режиме.

Если ветка `gh-pages` уже существует на remote, сначала получи её на хосте, чтобы новый коммит продолжил её историю:

```sh
git fetch origin gh-pages:refs/heads/gh-pages
```

Затем отправь ветку с хоста обычной командой:

```sh
git push origin gh-pages
```

Если имя ветки или remote отличаются, укажи `-e PAGES_BRANCH=site-pages` и при необходимости `-e PAGES_REMOTE=upstream`; последний влияет на подсказку команды push, но не вызывает соединение с remote. После изменения `package-lock.json`, `Dockerfile` или `deploy-pages.sh` повторно выполни `docker build`. Контейнер оставляет временную копию проекта внутри себя для осмотра и не удаляет её автоматически. `docker run` без `--rm` сохраняет остановленный контейнер; посмотреть его можно через `docker ps -a`.

## Ограничения

- Данные и фотографии некоторых объектов неполны; отсутствующие фотографии обозначены явно.
- В переключателе доступны Тбилиси, Батуми и Кутаиси; данные зданий пока есть только для Тбилиси. Векторные улицы, парковые зоны и музеи покрывают административную территорию Тбилиси; силуэты обычных зданий сохранены только в центральной подложке и по умолчанию скрыты.
- Внутренний предпросмотр недоступен в данном окружении: визуальная, мобильная, геолокационная и автономная E2E-проверки в браузере не выполнены.
- Для полноценного редакционного выпуска нужны проверка 100 контуров, дат, авторства и фотографий, повышение полноты галерей и реализация расширенной схемы фаз из исходного плана.
