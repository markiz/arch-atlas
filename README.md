# Архитектурный атлас Тбилиси

Статический веб-атлас архитектуры Тбилиси: карта с контурами исторических зданий, каталог с поиском и фильтрами, карточка здания с фотографиями и источниками. Интерфейс на русском, данные — локальные.

Стек: React, TypeScript, Vite, Leaflet. Сайт собирается в статический `dist/`, работает на обычном HTTP-хостинге и в подкаталоге GitHub Pages.

## Что входит в репозиторий

- `src/` — интерфейс: карта, каталог, поиск, фильтры, галерея, геолокация по кнопке.
- `data/atlas/tbilisi/<id>.json` — исходные карточки зданий, по одному JSON на объект.
- `data/aux/tbilisi/` — редактируемые справочники стилей, архитекторов, районов и подписей датировок.
- `data/landmarks/tbilisi/` — карточки ориентиров.
- `data/photos/tbilisi/` — фотографии в WebP и sidecar-метаданные; имена файлов — SHA-256 содержимого.
- `raw/osm/` — сохранённые выгрузки OpenStreetMap, из которых собираются слои карты.
- `scripts/` — только повторяемые инструменты сборки и проверки.
- `tests/` — тесты сборщиков и вспомогательных модулей.
- `docs/` — постоянная документация, которая остаётся верной при развитии проекта.
- `work/` — локальные кэши, временные ресурсы и исследовательские материалы; каталог в `.gitignore`.
- `archive/` — старые документы и история решений; не является действующей документацией.

`public/atlas/` — генерируемый каталог: бандлы зданий и ориентиров, манифест, слои карты и опубликованные фотографии. В Git он не хранится; исходники лежат в `data/` и `raw/`.

## Требования

Для разработки требуется только docker. Node, python и тому подобные инструменты зашиты в образ.

## Быстрый старт


```sh
make dev
```

При первом запуске соберётся Docker-образ. Откройте `http://localhost:5173/`. Vite пересобирает данные при изменении `data/atlas/`, `data/landmarks/`, `data/aux/`, `data/photos/` и `raw/` и перезагружает страницу.

Порт можно изменить: `make dev DEV_PORT=4173`.

Опционально можно добавить свой google maps api ключ, это необходимо для точного определения place id для ссылки геометки.

## Основные команды

Сборка и запуск выполняются в контейнере; на хосте нужны только `make` и Docker.

| Команда | Что делает |
|---|---|
| `make image` | Собирает Docker-образ с зависимостями и инструментами. |
| `make dev` | Запускает dev-сервер Vite с горячей пересборкой данных. |
| `make build` | Собирает сайт и создаёт локальный коммит в ветке `gh-pages`; push не делает. |
| `make push` | Отправляет ветку `gh-pages` в remote. |

`make dev` собирает образ при необходимости. Для `make build` сначала выполните `make image`; после чистой установки достаточно `make dev`, зависимости и инструменты уже входят в образ.

`make codex` и `make deepseek` запускают соответствующие контейнеры для работы с проектом.

## Как устроена сборка

1. `scripts/build-map-layers.mjs` проверяет хеш входов и при необходимости запускает `scripts/build-data.py`.
2. `scripts/merge-aux.mjs` собирает городские справочники в `data/aux/tbilisi.json`.
3. `scripts/create-photo-thumbs.py` создаёт превью, `scripts/sync-photos.mjs` публикует фотографии.
4. `scripts/rate-photos.py` считает рейтинг снимков.
5. `scripts/assemble-atlas.mjs` и `scripts/assemble-landmarks.mjs` упаковывают карточки.
6. `scripts/create-manifest.mjs` считает размеры и SHA-256, затем `tsc` и `vite build` собирают `dist/`.

Слои карты пересобираются только при изменении `raw/`, переводов или самого `build-data.py`; отметка лежит в `.cache/`.

## Данные

- Карточка здания хранит названия и адреса на четырёх языках, описание, историю, координаты, контур `Polygon`/`MultiPolygon` и упорядоченный список фотографий. Стили, архитекторы, районы и подписи датировок остаются ссылками в `data/aux/tbilisi/`.
- Координаты в JSON и GeoJSON — `[longitude, latitude]`; Leaflet получает `[latitude, longitude]`.
- Неизвестные даты, авторы, стили и истории не выдумываются: в карточке остаётся явное «не установлено».
- Фотография адресуется по SHA-256 своих байтов. Рядом с `data/photos/tbilisi/<sha256>.webp` лежит `<sha256>.metadata.json` с автором, лицензией, источником, изменениями, размерами и рейтингом.
- `public/atlas/`, `data/aux/tbilisi.json`, `data/thumbnails/`, `dist/` и `.cache/` генерируются. Не редактируйте их вручную.

Карта использует локальную векторную подложку и не запрашивает растровые тайлы или внешние карты. Для данных OpenStreetMap сохраняется атрибуция ODbL.

## Публикация

```sh
make image
make build   # собрать и создать локальный коммит в gh-pages
make push    # отправить gh-pages в remote
```

`make build` собирает сайт во временной копии и создаёт локальный коммит в ветке `gh-pages`; push не выполняется, свежий `dist/` в рабочем дереве не остаётся. Ветка публикации собирается заново, поэтому удалённые файлы не накапливаются. `make push` выполняет `git push` с хоста, поэтому нужны ваши Git-учётные данные. Для другого remote или ветки:

```sh
make build REMOTE=upstream BRANCH=site-pages
make push REMOTE=upstream BRANCH=site-pages
```

Для произвольного статического хостинга возьмите содержимое ветки `gh-pages` после `make build`. Проверять сайт нужно по HTTP(S), а не через `file://`: иначе не работают геолокация и проверка целостности файлов.
