# Объекты без Place ID

Снимок: 7 ноября 2026 года. В атласе 403 карточки, Place ID есть у 359, отсутствует у 44. Все 359 меток находятся не дальше 15 м от контура, из них 348 — не дальше 10 м; 11 остаются в диапазоне 10–15 м. Отсутствие ID не означает, что у здания нет адреса в Google: это может быть дом без отдельной карточки, объект во дворе, здание внутри большого парка или кладбища, адресная точка дальше 15 м от контура или просто несовпадение в радиусе проверки.

Пакетная проверка 7 ноября 2026 года добавила 290 ID, после чего расстояние от каждой метки до контура было измерено по Polygon/MultiPolygon. Для 41 карточки ID заменён на более близкую адресную точку с совпадающим номером дома и улицей, для 33 — удалён: Google не даёт точки ближе 15 м, и карточка теперь открывает поиск по адресу. Затем 10 ID возвращены после ручной проверки: 9 именованных достопримечательностей (бани, церкви, метро, дворец) по текстовому поиску и дом Леси Украинки, 6 / Жвании, 9 по старому имени улицы Zubalashvili (точка «9/6» внутри контура). Итог: 359 ID, ни одна метка не дальше 15 м от контура, 11 — в диапазоне 10–15 м. Все 359 проверены через Places API (New) Place Details: резолвятся. Это автоматическая проверка адресного соответствия, а не полная ручная сверка каждого корпуса; при редактировании карточки ID всё равно нужно сверять с контуром.

В интерфейсе карточка без Place ID открывает поиск Google Карт по названию и адресу; ссылка на голую координату остаётся только при пустом адресе. Цель — ни одной карточки с координатной ссылкой: `scripts/check-data.mjs` требует `googlePlaceId` или непустой `addresses.en` и печатает покрытие Place ID. Правило прежнее: Place ID добавляется только после проверки, что он относится к тому же зданию и адресу. Адресный ID (`kind=house`) и именованная достопримечательность — разные вещи; в карточке это различается через `googlePlaceIdSource`.

## Как получить актуальный список

```sh
node --input-type=module -e "
import fs from 'fs';
const b = JSON.parse(fs.readFileSync('public/atlas/buildings.json', 'utf8'));
for (const x of b.filter((y) => !y.googlePlaceId)) {
  console.log([x.id, x.name, x.address].join('\t'));
}
"
```

Собранный `buildings.json` здесь используется только для удобства: `name` и `address` — производные поля. Источник — `data/atlas/tbilisi/<id>.json`, где имя и адрес лежат в `names`/`addresses`. Список стоит фильтровать по району или адресу, а не просматривать целиком. Для новых проверок использовать `scripts/batch-google-addresses.py`: он работает с допуском 5 м и сохраняет результат в отдельный отчёт, не меняя карточки.

## Порядок

1. Разобрать `addresses.en`, `addresses.ka` и `addresses.ru` на отдельные адреса (угловые дома — через ` / `), убрать пояснения в скобках.
2. Выполнить прямое геокодирование Google: `address=<адрес>, Tbilisi, Georgia` (или `თბილისი, საქართველო` / `Тбилиси, Грузия`). Принимать только `street_address`/`premise`, у которых совпадают номер дома (включая `42a`, `42ა`, диапазоны), название улицы и **точка не дальше 15 м от контура** (цель — 10 м). Если адресная точка дальше, попробовать обратное геокодирование в точке здания; если и там нет совпадения номера и улицы — удалить ID, а не оставлять далёкую метку.
3. Проверить выбранный ID через Places API (New) Place Details: объект существует, адрес и координата относятся к нужному зданию, расстояние до контура не больше 15 м. Записать `googlePlaceId` и `googlePlaceIdSource` — обычную ссылку Google Maps без ключа API.
4. Если адрес не находится, для именованной достопримечательности использовать текстовый поиск по названию и проверить расстояние. Если и это не дало результата, оставить полный адрес: интерфейс откроет поиск по названию и адресу.
5. Не подставлять координату как замену. `scripts/check-data.mjs` требует `googlePlaceId` или непустой `addresses.en` и печатает покрытие; карточка без обоих полей не проходит проверку.

## Что проверять

- Точка Place ID лежит не дальше 15 м от контура (цель — 10 м), а не у соседнего корпуса.
- Адрес в Google совпадает с реестровым/атласным, включая буквы и дроби.
- Для именованной достопримечательности тип не `premise`/`street_address`.
- Не переносить Place ID с соседнего объекта и не считать его доказательством исторической даты или авторства.
