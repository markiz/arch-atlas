# Архив документации

Здесь лежат исторические документы проекта. Они сохранены для контекста и не являются действующим контрактом: числа, требования и ссылки в них относятся к дате создания.

| Документ | Дата / состояние | Почему в архиве |
|---|---|---|
| [implementation-plan.md](implementation-plan.md) | Версия 1.0, 31 октября 2026 | Исходный план и задания для первой реализации; часть решений позже изменена |
| [status-2026-10-31.md](status-2026-10-31.md) | Снимок на 31 октября 2026 | Ранний статус на 100 карточек; сохранён как история, не как текущее состояние |
| [google-place-id-manual-review-100.md](google-place-id-manual-review-100.md) | Снимок на 31 октября 2026 | Список 12 объектов без Place ID для набора из 100 карточек; набор с тех пор вырос |

## Что считать актуальным

- [README.md](../../README.md) — запуск, сборка и публикация.
- [status.md](../status.md) — текущее состояние сборки.
- [location-data-collection.md](../location-data-collection.md) — правила сбора данных и проверок.
- [research-pipeline.md](../research-pipeline.md) — схема конвейера и скрипты очереди.
- [research-queue-progress.md](../research-queue-progress.md) — текущий регистр очереди.

Исследовательские файлы `docs/research-*.md` остаются в корне `docs/`, потому что на них ссылаются друг на друга и на них опирается текущая очередь. Это датированные снимки исследования, а не инструкции.

## Правило архивации

Исторические документы не удаляются: при замене текущего документа старый переносится сюда с датой в имени. Ссылки в актуальных документах должны указывать либо на текущую версию, либо на конкретный файл в архиве, а не на устаревший путь.
