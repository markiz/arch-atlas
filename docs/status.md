## Сделано

- Исходники карточек — по одному pretty-JSON на объект в `data/atlas/tbilisi/`; `scripts/assemble-atlas.mjs` упаковывает их в `public/atlas/buildings.json` перед сборкой и в dev-сервере, который перезагружает страницу после правки файла.
- `public/atlas/` целиком генерируется и больше не хранится в Git: бандл, манифест и слои карты пересоздают `npm run build`, `npm run check` и `npm run dev`. Слои из `raw/` пересобираются только при изменении хеша входов (`scripts/build-map-layers.mjs`, отметка в `.cache/`), поэтому первый запуск на чистом клоне занимает около 5 с и требует Python 3 — он есть в Docker-образе.
- Вторичные справочники города разложены по видам в `data/aux/tbilisi/{styles,architects,districts,year-labels}.json`; `scripts/merge-aux.mjs` склеивает их в `data/aux/tbilisi.json` для сборки. Старый общий `data/building-attribute-translations.json` удалён, карточки ссылаются на прежние стабильные ID.
- 2 ноября 2026 года атрибуция районов приведена к 15 каноническим историческим районам. Из `districts.json` удалены `tbilisi` и `old-tbilisi`, все 403 карточки и 131 ориентир получили конкретный район; историческое ядро — `kala`, а не «Старый Тбилиси». У каждого района добавлены упрощённые полигоны (`geometry`, `geometrySource`) из OSM, покрывающие город; все карточки и ориентиры проверены на попадание в свой район. Правила и таблица — [district-attribution.md](district-attribution.md).
- Все объекты имеют Polygon/MultiPolygon; составные отношения OSM разобраны в реальные контуры. Цвет отображается на всех масштабах.
- Карта, каталог, поиск и фильтры по датам, архитекторам и стилям; переключатель Тбилиси, Батуми и Кутаиси, для двух последних — честное пустое состояние.
- Галерея и атрибуция для каждого изображения: автор, лицензия и ссылка на источник в инспекторе и в полноэкранной подписи; записи без фото обозначены явно. В основном режиме галерея и карточка каталога сортируются по детерминированному `rating`; если у объекта есть три снимка >50, снимки <50 скрываются. Фотографии не входят в начальную загрузку: каталог лениво подгружает превью видимых карточек, а при выборе объекта сначала загружаются все превью, затем полные файлы галереи.
- Геолокация только по нажатию, с обработкой отказа, ошибки и выхода за пределы подробной карты.
- Данные, геометрии, проверка фото и тесты фильтрации проходят; все ресурсы входят в локальный SHA-256 манифест. Исходники фотографий лежат в `data/photos/<city>/<sha256>.webp` с метаданными в `<sha256>.metadata.json` (включая фактические `width`/`height` WebP), превью — в `data/thumbnails/<city>/<sha256>.webp` (до 720 px, пропорции сохранены). Имя файла — SHA-256 байтов, поэтому изменение снимка автоматически даёт новый id; 955 записей используют 951 уникальное изображение. `data/thumbnails/` не хранится в Git, публикуемые зеркала `public/atlas/photos/` и `public/atlas/thumbnails/` генерирует `scripts/sync-photos.mjs`, недостающие превью создаёт `scripts/create-photo-thumbs.py` при сборке и `npm run photos:thumbs`.
- Фотографии: приоритет свободным лицензиям; ширина до 1920 px для свободных снимков и до 1200 px для неизвестных/коммерческих, без апскейла. Галереи добиваются до трёх разных кадров, дубли отбрасываются по perceptual hash, адрес проверяется по категориям файла. При отсутствии свободного снимка используется фото реестра с пометкой «лицензия не установлена». Для реестра `scripts/fetch-registry-photos.py --review` собирает все `photoIds` записи и контактные листы, а `--apply` берёт ручной отбор из `data/registry-photo-selection.json`; маленький дубль кадра заменяется более крупной версией, галерея — три-четыре разных вида. Пакетная подготовка — `scripts/batch-registry-review.py`, нарезка — `scripts/plan-registry-review.mjs`, слияние — `scripts/merge-registry-selections.mjs`; отборы лежат в `work/registry-batch/selections/`. Конвейер Commons — `scripts/collect-photo-candidates.py` + `scripts/apply-photo-candidates.py`; полная политика — [photo-policy.md](photo-policy.md).
- Проверка маленьких снимков 1 ноября 2026 года: 326 записей ниже лимита повторно запрошены у источника, 11 фото восстановлены до 960–1920 px (8 до 1280, 1 до 960, 2 до 1920), затронуто 10 карточек, ошибок нет. Реестр тогда отдавал тот же оригинал 250–640 px, поэтому 292 его снимка не увеличились; пакетный прогон ниже заменил маленькие дубли 640 px. Скрипт — `scripts/upgrade-photo-sources.py` (`npm run photos:upgrade`); отчёт — `work/photo-research/source-upgrades.json`.
- CLIP-классификатор удалён: на 30 случайных фото он дал precision 0.825, recall 0.322 и 0/30 точных совпадений набора. Все **951 уникальное изображение** размечены моделью вручную по контактным листам по 6 фото, полный one-pass проход завершён: 33 content-тега и 7 quality-тегов. Quality-слой: `low-resolution` — 749, `occluded` — 24, `foreground-distraction` — 10, `subject-far` — 5, `tilted` — 2, `cluttered` — 2, `dark` — 1; `blurry` не встретился. Чаще всего: `facade` — 944, `street` — 690, `window` — 679, `tree` — 548, `balcony` — 429, `car` — 396, `arch` — 166, `fence-wall` — 101, `people` — 93, `multiple-buildings` — 89, `dome` — 71, `shopfront` — 48. У 210 снимков Commons есть сырые `sourceTags`. Таксономия — `data/photo-visual-tags.json`, служебный процесс — `scripts/photo-visual-review.py`, `npm run photos:review-status`.
- Детерминированный рейтинг посчитан для всех **951** снимка после смены формулы: средний **65.6**, минимум 9, максимум 100; **57** ниже 50, **696** — 50–69, **81** — 70–84, **117** — 85–100, **12** — ровно 100. У 751 снимка с шириной <800 максимум 70; у 12 ночных кадров диапазон 45–80. `low-resolution` остался в таксономии с нулевым весом, а низкое разрешение штрафуется линейно через `resolutionFactor` (1.0 при 800+ px, 0.5 при ширине, стремящейся к 0). Скрипт — `scripts/rate-photos.py` (`npm run photos:rate`), `build` пересчитывает рейтинг, `check` проверяет актуальность. У 154 объектов три снимка, у 46 — четыре; 181 галерея имеет три сильных кадра >50, в 6 из них правило скрывает по одному слабому кадру (всего 6 фотографий).
- Батч галерей 1 ноября 2026 года добавил 54 свободных снимка Commons (210 записей с CC0/PD/CC BY/CC BY-SA) и обновил 126 существующих до ширины до 1920 px (по размеру исходника); тогда фото реестра остались 292. Кандидаты искались по улице и номеру дома, P180/P18, тегу OSM и названию, проверялись по категориям файла и почти-дублям; ручной отбор прошли 76 кадров, из них 54 добавлены после дедупликации. Тогда получилось 314 карточек с одной фотографией, 65 — с двумя, 19 — с тремя, одна — с четырьмя; у большинства обычных исторических домов в Commons просто нет трёх проверяемых снимков.
- Пакетный прогон реестра 1 ноября 2026 года: 272 карточки, **728** новых файлов, **288** старых реестровых снимков заменено. 263 отбора сделаны по контактным листам, 9 пилотных — отдельно, ручной отбор `osm-1207173721` проверен заново. Итог: 89 карточек с одной фотографией, 110 — с двумя, 154 — с тремя, 46 — с четырьмя, 4 без фото. Многие записи содержат только дворы, ворота, лестницы и фрагменты, поэтому меньше трёх общих видов — честный пробел.
- Пилот реестра 1 ноября 2026 года: `osm-1207173721` (запись 3359) было 1 фото 327×208, стало 3 — 309073 640×425 (крупный дубль), 309075 (вид вдоль фасада) и 309085 (площадь с застеклёнными галереями). Кадры 309080/309081 с современным стеклянным соседом отклонены. По новой формуле рейтинг 59–61: ширина 640 px даёт `resolutionFactor` 0.90, площадь кадра выросла в 4–9 раз. Отчёт — `work/registry-photos/applied.json`.
- Для объектов без надземного контура поддерживается `geometryRole=heritage_boundary`: карта рисует охраняемую границу пунктиром и предупреждает, что это не footprint здания.
- Ориентиры подложки стандартизированы: 131 ориентир вынесен в `data/landmarks/tbilisi/*.json` и собираются в `public/atlas/landmarks.json`. Схема — [landmark-schema.md](landmark-schema.md); у 67 объектов описание проверено по источникам, у 64 оно черновое, рейтинг значимости предварительный.
- Добавлены детерминированный сбор фактов по очереди, отчёт и валидатор карточек: `scripts/queue_collect.py`, `scripts/queue_report.py`, `scripts/validate_cards.py`.
- Финальный шаг добавления в атлас — ручная проверка названий: редактор сверяет карточку с 3–5 ближайшими объектами и всем ансамблем, проверяет четыре языка и термины по единому словарю `data/name-translation-rules.json`. Результат фиксируется в `work/queue/<n>/name-review.md` по чеклисту [name-consistency-review.md](name-consistency-review.md); это не автоматическая замена текста.
- Все длительные загрузчики, сборщики и проверки печатают прогресс с ETA в stderr; общие helper'ы — `scripts/progress.py` и `scripts/lib/progress.mjs`. Правила — [long-running-scripts.md](long-running-scripts.md).

## Требуется дальше

1. Пройти браузерную проверку: карта, мобильная панель, клавиатура, галереи и каждое состояние разрешений геолокации; проверить работу после загрузки без внешних карт и тайлов.
2. Ручная редакционная проверка контуров, дат, авторов и соответствия фотографий конкретным зданиям; отдельная проверка прав на архитектурные произведения и лицензии.
3. Пять очередей по 200 разобраны: 303 добавлено, 513 hold/reject с причинами; 60 READY пятой очереди ждут перевода. Для возврата приоритетны hold с сильной идентичностью и хорошей геометрией; следующая очередь пока не отбиралась.
4. Выборочно проверить новые галереи, добрать третьи снимки для карточек с 1–2 фото, где есть проверяемые общие виды, и заменять fallback реестра свободными фото по мере появления; заполнять неизвестные поля только по проверяемым источникам.
5. Добавить реальные наборы данных Батуми и Кутаиси и включить их в переключатель.
6. Дополнить модель фаз и источников; обеспечить множественный выбор фильтров и сохранение состояния в ссылке.
7. Расширить слой ориентиров по процедуре [landmark-expansion.md](landmark-expansion.md): собрать пул кандидатов, отобрать топ-100 по значимости, дополнить черновые описания и подключить `public/atlas/landmarks.json` к карте вместо текущего OSM-обнаружения.

## Ограничения

- В текущем окружении не выполнялась полноценная браузерная E2E-проверка: визуальное поведение, мобильная панель, сетевая изоляция после загрузки и геолокация требуют отдельного прогона.
- Для Батуми и Кутаиси нет наборов зданий; переключатель показывает пустое состояние.
- Неизвестные даты, авторы, стили и фотографии не заполняются предположениями; отсутствие данных обозначено в карточке.
- Пять очередей разобраны; следующая очередь ещё не отбиралась.
- Публикация и push выполняются пользователем; см. ограничения в [README.md](../README.md).

Исторические документы и ранние снимки состояния сохранены в [архиве](archive/README.md); карта research-файлов — в [research-index.md](research-index.md); исходный план проекта больше не является действующим контрактом.
