# Значимость объекта

Атлас — кураторская коллекция архитектуры, а не каталог учреждений. Объект попадает в `data/atlas/` не потому, что у него есть имя, адрес, полигон и фотография, а потому что его архитектурная или историческая ценность подтверждена источником.

Это правило действует для всех типов и для всех карточек, включая короткие карточки без описания. «BASIC» — это формат карточки, а не основание для публикации.

## Тест значимости

Кандидат допускается к `draft`, если выполнены **не менее двух** условий и нет ни одного дисквалификатора. Явно подтверждённый охранный статус считается сильным доказательством и позволяет `keep` без второго критерия.

1. **Авторство.** Назван архитектор или инженер с опубликованным наследием, либо документированный конкурс, премия или государственный заказ с авторским проектом.
2. **Публикация.** Объект вошёл в профессиональный гид, монографию, архив, реестр памятников, исследовательский проект или профильную архитектурную периодику.
3. **Градостроительная или типологическая роль.** Здание формирует узел, площадь, улицу или доминанту; представляет редкую типологию, конструкцию или градостроительное решение, а не типовой повтор.
4. **Сохранность.** Сохранены первоначальный объём, фасад, конструкция, мозаики или рельефы; перестройки локальны и обратимы.

Охранный статус (`heritage`) — отдельный критерий: памятник культуры, объект культурного наследия, `spomenik kulture`, «заштићено».

## Что не является доказательством

- наличие в OSM, Wikidata, QID, полигона или фотографии;
- название, функция, арендатор, вывеска, событие;
- дата основания учреждения (школа основана в 1967 году — не год постройки корпуса);
- длинный текст об учреждении, числе классов, кабинетов или услуг;
- статья в Википедии об учреждении без описания здания, автора и архитектурных особенностей. Википедия — указатель, а не замена публикации.

## Дисквалификаторы

- типовая панельная, школьная, детсадовская, поликлиническая или офисная застройка без индивидуального авторства и публикации;
- гараж, пристройка, сарай, хозяйственный блок;
- не здание: памятник, фонтан, ворота, мост, кладбище, участок, комплекс из многих корпусов;
- копия, новодел, «фасадная» реконструкция с новым объёмом;
- руина или фрагмент;
- значимость только из-за арендатора, вывески или события.

## Вердикты

- `keep` — значимость подтверждена, карточка может публиковаться.
- `review` — доказательств недостаточно или они противоречивы; карточка не удаляется автоматически, но публиковать её как значимую нельзя.
- `remove` — есть дисквалификатор или ни одного критерия; карточка удаляется из `data/atlas/`, а не маскируется пустыми полями.

Решение и доказательства хранятся в `data/significance/<city>.json`:

```json
{
  "schema": 1,
  "city": "belgrade",
  "updatedAt": "2026-11-22",
  "policy": "docs/significance.md",
  "cards": {
    "osm-way-...": {
      "verdict": "keep",
      "criteria": ["authorship", "publication"],
      "disqualifiers": [],
      "reason": "кратко, почему объект значим",
      "evidence": ["https://...", "поле карточки/источник"]
    }
  }
}
```

Реестр обязателен для каждого города, где он уже заведён: `npm run check` проверяет, что у каждой карточки есть запись, `keep` имеет не меньше двух критериев (или `heritage`) и доказательство, а записей `remove` не осталось. Новые карточки без записи в реестре не публикуются.

## Квоты и приоритеты

Квоты по типам — потолок, а не план. Если значимых образовательных объектов на 66 не набралось, публикуется меньше; добирать квоту типовыми школами запрещено. Публичный пул означает обязательный разбор, а не обязательную публикацию.

Тест применяется до `draft`, а не после написания текста. Для модернизма и современной архитектуры вне реестра дополнительно действует [раздел 9.1](new-object-pipeline.md#91-модернизм-и-современная-архитектура-вне-реестра).

## Аудит существующих карточек

Аудит идёт батчами в субагентах с чистым контекстом: агент получает только карточки, рубрику и источники, возвращает `keep`/`review`/`remove` с доказательствами. Оркестратор сводит вердикты, удаляет `remove` и записывает реестр. Разовые отчёты и батчи лежат в `work/`; реестр — в `data/significance/<city>.json`.

Проверка:

```sh
npm run check:significance            # отчёт; review допустим
npm run check:significance -- --strict # перед публикацией: review тоже ошибка
npm run check
```
