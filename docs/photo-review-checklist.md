# Чеклист одного прохода разметки фотографий

Один проход — это **одно чтение листа**, после которого модель назначает и content-теги, и quality-теги. Это не два отдельных просмотра: сначала по всем шести кадрам листа выставляется содержание, затем по тем же шести кадрам — качество.

## Вход

- Контактный лист `work/photo-research/review/sheet-NNN.jpg` с шестью фото и подписями `NNN.P <id8>`.
- `work/photo-research/review/index.json` — полные id, порядок и размеры сохранённых файлов.
- `data/photo-visual-tags.json` — единственный допустимый словарь тегов (43 тега).

Не смотрите старые `visualTags`, sidecars и результаты классификаторов: лист должен быть единственным визуальным источником.

## Content: что на фото

Для каждого кадра выберите применимые теги из групп `scene`, `object`, `condition`:

- `scene` — один или несколько: `facade`, `interior`, `street`, `courtyard`, `multiple-buildings`, `panorama`, `aerial`;
- `object` — только явно видимые: `balcony`, `window`, `door`, `roof`, `dome`, `tower`, `arch`, `column`, `staircase`, `fence-wall`, `detail`, `plaque`, `people`, `car`, `tree`, `sky`, `water`, `construction`, `scaffolding`, `ruin`, `graffiti`, `shopfront`, `air-conditioner`, `street-lamp`, `sign`;
- `condition` — `nighttime`, `snow`, `rain`.

Правила:

- не угадывайте: если объект не виден или неразличим, тег не ставится;
- у каждого фото должен быть хотя бы один `scene`-тег;
- `interior` исключает внешние `facade`/`street`/`courtyard`/`multiple-buildings`/`panorama`/`aerial`, но объекты внутри (окно, дверь, колонна) остаются;
- порядок тегов — как в таксономии.

## Калибровка: когда тег считается достаточным

Правило «видно» само по себе слишком широкое. Перед полным проходом зафиксированы пороги:

### Content

- **Архитектурные элементы субъекта** — `window`, `door`, `roof`, `balcony`, `arch`, `column`, `staircase`, `dome`, `tower`, `shopfront` — ставятся, если это видимая часть здания-субъекта, даже если она небольшая. Не ставятся для чужих зданий на заднем плане.
- **`window`** — не ставится, если окна видны только как ряд мелких точек на дальнем фоне.
- **`door`** — только явный вход или дверное полотно, не любое тёмное пятно.
- **`roof`** — если видна крыша или её заметная часть; тонкая кромка на границе кадра не считается.
- **`air-conditioner`** — только отчётливо различимые блоки на фасаде субъекта. Белые прямоугольники, в которых нельзя уверенно узнать кондиционер, не тегируются.
- **`people`** — только узнаваемые фигуры. Люди размером в несколько пикселей не тегируются.
- **`car`**, **`street-lamp`**, **`sign`** — если объект различим и играет роль в кадре; случайные мелкие пятна не считаются.
- **`tree`** — если дерево/зелень — заметная часть композиции или переднего плана. Дальняя зелень по краю кадра не тегируется.
- **`detail`** — только осознанный крупный план архитектурной детали, а не любой фрагмент фасада.
- **`ruin`** — только явно разрушенное здание/конструкция. Облупившаяся краска, повреждённая штукатурка и старый интерьер — это `detail`/`interior`, но не `ruin`.
- Если сомневаетесь, ставьте ли тег, — **не ставьте**. Пропуск лучше шума.

### Quality

- **`foreground-distraction`** — объект на переднем плане, который является первым визуальным якорем или занимает заметную часть нижней трети кадра. Кот на 068.6 qualifies; мелкий прохожий у края — нет.
- **`subject-far`** — объект атласа занимает меньше примерно четверти высоты кадра или явно находится на заднем плане.
- **`occluded`** — скрыта существенная часть фасада/входа. Ветка или тонкое дерево перед окном — ещё не `occluded`.
- **`cluttered`** — несколько конкурирующих объектов, и глаз не находит главное. Использовать редко.
- **`tilted`** — заметный наклон горизонта или вертикалей. Обычная перспектива не считается.
- **`dark`** — явная недоэкспозиция, при которой теряются детали. Сумерки с читаемым фасадом — это `nighttime`, но не `dark`.
- **`blurry`** — явный смаз или расфокус. На листе 6-up не тегировать сомнительные случаи.
- **`low-resolution`** — объективно: `width < 800` в `index.json`. Обсуждению не подлежит.

### Эталонные решения

- 068.6 (`cdaa5a91`): `facade`, `street`, `window`, `tree`, `street-lamp`, `tilted`, `foreground-distraction`, `subject-far`.
- 062.5: крошечные сидящие фигуры → `people` не ставится.
- 067.2: повреждённый интерьер → `interior`, `detail`; `ruin` не ставится без явного разрушения.
- 069.5: синий час, фасад читается → `nighttime`, `dark` не ставится.
- 061.1: мелкие белые блоки, неразличимые как кондиционеры → `air-conditioner` не ставится.

## Quality: пригоден ли кадр для атласа

По тем же шести кадрам, не перечитывая лист, проверьте quality-теги:

- `foreground-distraction` — крупный посторонний объект на переднем плане (кот, машина, человек, дерево, столб) перетягивает внимание;
- `subject-far` — объект атласа мал или находится на заднем плане;
- `occluded` — объект частично закрыт другим зданием, деревом, стеной или транспортом;
- `cluttered` — много конкурирующих объектов, трудно выделить главное;
- `tilted` — заваленный горизонт;
- `blurry` — смазанный или расфокусированный кадр;
- `dark` — недоэкспонированный кадр;
- `low-resolution` — ширина файла в `index.json` меньше 800 px (не путать с размером ячейки на листе).

Quality-теги не отменяют content-теги. Фото может быть `facade` и одновременно `tilted` или `subject-far`.

## Порядок работы

1. Открыть лист.
2. По каждому из шести кадров выписать content-теги.
3. По тем же кадрам, не закрывая лист, добавить quality-теги.
4. Сверить: нет ли дублей, все ли теги из таксономии, у каждого фото есть `scene`-тег.
5. Записать массив тегов в JSON батча в порядке фото на листе.

## Пример: 068.6 (`cdaa5a91`, дом 149)

Содержание: `facade`, `street`, `window`, `tree`, `street-lamp`.

Качество:

- на переднем плане кот → `foreground-distraction`;
- здание в глубине кадра → `subject-far`;
- горизонт завален → `tilted`.

Итог:

```json
["facade", "street", "window", "tree", "street-lamp", "tilted", "foreground-distraction", "subject-far"]
```

## Формат результата

```json
{
  "061": [["facade", "balcony"], ["..."], ["..."], ["..."], ["..."], ["..."]],
  "062": [["..."], ["..."], ["..."], ["..."], ["..."], ["..."]]
}
```

Ключ — номер листа, значение — ровно шесть массивов в порядке `index.json`. Пустых массивов быть не должно.
