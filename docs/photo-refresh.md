# Обновление фотографий существующих карточек

Постоянная процедура: после публикации объект не считается «закрытым». У карточки
могут появиться лучшие свободные снимки, а у новых объектов — только одно фото.
Эта дорожка ищет **новые фотографии для уже существующих карточек**, проверяет
права и совпадение объекта и передаёт принятые снимки в общий фотоконвейер.

## 1. Когда запускать

- после публикации новой партии карточек;
- для карточек без фото (`photos = []`);
- для карточек с одним фото;
- для карточек, где максимальный рейтинг фото ниже 60;
- по запросу редактора для конкретного объекта.

Карточки с тремя и более сильными фото (> 70) не трогаем без причины: цель —
закрыть пробел, а не заменить хорошее.

## 2. Отбор карточек

Приоритет:

1. `photos = []` — обязательный разбор;
2. ровно одно фото с рейтингом < 60;
3. два фото, оба < 55;
4. только что опубликованные карточки (проверить, нет ли второго ракурса).

Батч — 5–10 карточек на субагента. Список фиксируется в
`work/photo-refresh-<date>/assignment.json`, чтобы прогон был воспроизводим.

## 3. Источники и лицензии

Разрешены только свободные лицензии:

- Wikimedia Commons: `CC0`, `Public domain`, `CC BY`, `CC BY-SA` (без `NC`/`ND`);
- Википедия: основное изображение статьи (P18) — только если оно на Commons;
- официальные сайты и Flickr — только при явной свободной лицензии в метаданных;
- реестровые и «All rights reserved» фото не импортируются.

Для каждого кандидата сохраняются `author`, `license`, `licenseUrl`, `source`
(страница файла), `width`, `height`. Автор и лицензия — латиницей, как в sidecar.
Кириллические и грузинские имена транслитерируются по словарю проекта
(например, «Александр Сигачёв» → `Alexander Sigachyov`), а не переписываются
на слух. `Unknown` допустим только для анонимного PD-снимка, не для CC.
Если лицензия не распознана — кандидат отклоняется, а не «уточняется» догадкой.

## 4. Поиск

1. Геопоиск Commons в радиусе 150–200 м от контура.
2. Поиск по названию объекта, историческому имени и адресу (ka/en/ru).
3. Категория Commons, если она есть у объекта или улицы.
4. Основное изображение статьи Википедии, если объект связан с QID.

Запросы к Wikimedia — с `User-Agent: ArchAtlas/1.0`, паузой не меньше 1,2 с,
кэшем по URL и backoff на 429. Заголовки не логируются.

Ответ HTTP 200 с телом `cirrussearch-too-busy` — это ошибка поиска, а не пустая
выдача. Такое тело нельзя кэшировать как «ничего не найдено»; запрос повторяется
с backoff. Иначе геопоиск молча теряет кандидатов.

## 5. Отсев и проверка

- **Дедуп:** SHA-256 против уже опубликованных фото; dHash/Hamming против
  существующих и других предложений. Полный дубль — reject.
- **Геометрия:** расстояние до контура; снимок должен относиться к объекту, а не
  к соседнему дому. `distanceM = null` допустим только для категории/описания
  файла, подтверждённых визуально; «нет координат» само по себе не доказательство.
- **Визуальная сверка:** сравнить кандидата с существующим фото или реестровым
  снимком. Подтверждать только тот же корпус/фасад. Детали, таблички, интерьеры и
  панорамы — только как дополнительные кадры, не как главное фото.
- **Качество:** ширина ≥ 1200 px, нет сильной расфокусировки, ночных и
  перекошенных кадров; дерево/машина не должны закрывать фасад.
- **Права на архитектуру:** для современных зданий проверить freedom of panorama;
  при сомнении — `needs_review`, а не `approved`.

## 6. Артефакт предложения

Субагент пишет только предложения, не меняя `data/`:

```json
{
  "schema": 1,
  "agent": "photo-1",
  "candidateId": "osm-…",
  "card": "data/atlas/tbilisi/osm-….json",
  "existingPhotos": [{"sha256": "…", "rating": 57}],
  "proposals": [
    {
      "title": "File:…",
      "pageUrl": "https://commons.wikimedia.org/wiki/File:…",
      "author": "…",
      "license": "CC BY-SA 4.0",
      "licenseUrl": "https://creativecommons.org/licenses/by-sa/4.0",
      "width": 3000,
      "height": 2000,
      "distanceM": 12.4,
      "thumbUrl": "…",
      "visualReview": "approved | needs_review | rejected",
      "reason": "тот же угловой фасад, что на существующем фото"
    }
  ],
  "notes": "…"
}
```

`visualReview=approved` означает: тот объект, свободная лицензия, автор известен,
дубля нет. `needs_review` — сомнение в объекте/правах; такой снимок не импортируется
без человека.

## 7. Импорт и публикация

Импортирует только оркестратор, одним пайплайном:

1. проверить proposal и лицензию;
2. скачать до 1600 px, конвертировать в WebP q82;
3. SHA-256 содержимого → `data/photos/<city>/<sha>.webp`;
4. sidecar: `author`, `license`, `licenseUrl`, `source`, `modifications`, `width`,
   `height`, `rating`, `visualTags`;
5. добавить SHA в `photos` карточки (не более трёх лучших; слабые не вытесняют
   сильные);
6. `python3 scripts/rate-photos.py`, `npm run check`;
7. отдельный коммит с указанием источника и автора.

Субагенты никогда не пишут в `data/`, `public/`, не делают коммиты и не меняют
существующие sidecar.

## 8. Параллельность

- 5–10 карточек на субагента. Эффективная одновременность — **2–3 субагента**:
  проверка 2026-11-14 с пятью агентами дала почти постоянные 429 на общем IP,
  backoff 10–90 с и потерю времени.
- У каждого — свой каталог `work/photo-refresh-<date>/<agent>/` и `status.md`.
- Общий rate limit на Wikimedia один. При 3+ агентах нужен общий файловый
  rate-gate (`work/photo-refresh-<date>/rate.lock` с `next_allowed_at`) или
  оркестратор разносит батчи по времени; параллельные агенты не должны
  суммарно устраивать burst.
- Оркестратор следит за 429 и останавливает/дробит батч, если ошибки идут
  подряд. Один агент не должен «обходить» лимит сменой endpoint того же хоста.
- Каждый субагент пишет `proposals.json` и `status.md`; оркестратор сводит их в
  `work/photo-refresh-<date>/summary.json` и публикует прогресс каждые 3–5 минут.
- Субагент с чистым контекстом получает полный бриф: пути, схему, ограничения,
  UA, лицензии и запрет на запись в `data/`.

## 9. Definition of done

Дорожка `done`, когда:

- для каждой карточки батча есть `approved`, `needs_review` или `rejected` с причиной;
- у approved есть страница файла, автор, лицензия и визуальная сверка;
- дубли отсеяны по SHA и dHash;
- предложения записаны в `proposals.json`, статус — в `status.md`;
- импортированные фото прошли `npm run check`, рейтинг пересчитан, sidecar полный.

## 10. Запрещено

- Импортировать фото с неясной лицензией «как временное».
- Выдавать соседний дом за объект по одному названию файла.
- Заменять сильное фото слабым или дубликатом.
- Писать в `data/` из субагента или публиковать без проверки оркестратора.
- Подставлять в запросы личные контакты, email или URL профиля.
